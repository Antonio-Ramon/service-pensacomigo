Gridify: filtro, ordem e página vindos da querystring

Aula 13 · Fatia 13 · Infra de listagem (issue 01 follow-up) + conformar Tags (issue 03) · ADR: arquitetura §7.1 / Decisão #19

Vitória desta aula: GET /api/v1/tags?filter=nome=*saude&orderBy=nome&page=1&pageSize=10 funciona — e você não escreveu nenhum if (filtro != null). Toda listagem do projeto passa a responder no mesmo envelope { items, totalItems }.

1. O problema que o Gridify resolve

Listagem cresce mal. Começa ListarTags(), depois vem "filtra por nome", "ordena por data", "pagina", e o handler vira uma escada de if. O Gridify move isso pra uma string na querystring traduzida pra SQL: 

?filter=nome=*saude          contém "saude"
?filter=slug=saude-mental    igual
?filter=nome=*a,slug=*b      vírgula = AND · barra vertical = OR
&orderBy=nome desc&page=2&pageSize=20

Isso é a DSL de filtro do Gridify. Ela vira Expression tree → o EF Core traduz pra SQL → filtra no banco, não em memória.

2. As 4 peças (e onde cada uma mora)

Domain/Common/Pagina.cs            envelope { Items, TotalItems }
Application/Tags/Listar/…Query.cs  : GridifyQuery — Page/PageSize/OrderBy/Filter
Persistence/…/TagRepository.cs     GridifyMapper (whitelist) + GridifyQueryableAsync
Web/Program.cs                     config global (camada de compat do EF)

2.1 A Query herda GridifyQuery

public class ListarTagsQuery : GridifyQuery, IQuery<Pagina<TagResponse>>;

Herdar já dá Page, PageSize, OrderBy e Filter. O controller recebe com [FromQuery] e o model binder preenche sozinho — os 4 parâmetros aparecem no Swagger de graça.

Pegadinha de C#: virou class, não record. Um record só pode herdar de outro record — GridifyQuery é classe comum. Foi por isso que a Query mudou de forma.

2.2 O Mapper é uma whitelist

private static readonly IGridifyMapper<Tag> Mapper = new GridifyMapper<Tag>()
    .AddMap("nome", t => t.Nome)
    .AddMap("slug", t => t.Slug);

Sem isso o cliente estaria filtrando por nome de propriedade da entidade — qualquer uma, inclusive as que você não quer expor. O mapper define o vocabulário público da listagem. Existe GenerateMappings() (mapeia tudo automaticamente); aqui a lista é curta, então é explícita — mais seguro e mais legível.

2.3 O repositório aplica tudo no IQueryable

if (string.IsNullOrWhiteSpace(consulta.OrderBy)) consulta.OrderBy = "nome";

var (total, query) = await db.Tags.AsNoTracking()
                             .GridifyQueryableAsync(consulta, Mapper, ct);
return new Pagina<Tag>(await query.ToListAsync(ct), total);

GridifyQueryableAsync devolve a contagem antes de paginar + o IQueryable já filtrado/ordenado/paginado. Duas idas ao banco: um COUNT e um SELECT … LIMIT/OFFSET.

Por que forçar um OrderBy padrão: sem ORDER BY, o Postgres não garante a mesma ordem entre duas consultas. A página 2 pode repetir ou pular linha da página 1. Paginação sem ordenação estável é bug silencioso.

2.4 Config global (uma vez, no Program.cs)

GridifyGlobalConfiguration.EnableEntityFrameworkCompatibilityLayer();
GridifyGlobalConfiguration.IgnoreNotMappedFields = true;

A primeira faz o Gridify gerar Expressions que o EF Core sabe traduzir pra SQL. A segunda faz campo não mapeado ser ignorado em vez de estourar exceção — cliente mandando ?filter=xpto=1 não derruba o endpoint.

3. O envelope: nunca devolva lista crua

public record Pagina<T>(IReadOnlyList<T> Items, int TotalItems);
{ "items": [ { "id": "…", "nome": "Saúde Mental", "slug": "saude-mental" } ],
  "totalItems": 1 }

Um array puro ([ … ]) não tem onde carregar o total — e sem total o frontend não monta paginador. Trocar depois é breaking change; por isso o envelope é o padrão desde o primeiro endpoint, mesmo onde é overkill (Tags é lookup pequeno). Consistência > economia pontual: a API inteira tem um contrato de listagem.

Nome Pagina<T> (não Paging<T>) porque o próprio pacote Gridify já tem um Paging<T> — nomes iguais no escopo dão CS0104: ambiguous reference. Domínio em pt-br resolve a colisão de graça.

4. Duas decisões de arquitetura embutidas

  • Pacote NuGet, não código vendorado. O service-escolaweb tem uma cópia interna do Gridify (com um DefaultOrderBy customizado). Aqui usamos Gridify + Gridify.EntityFramework do NuGet e resolvemos a ordem padrão com uma linha no repositório — menos código pra manter.
  • O repositório devolve Pagina<Tag> materializada, não (IQueryable, total). Sem AutoMapper/ProjectTo no projeto, expor IQueryable na Application só empurraria o EF pra dentro dela. O handler projeta com um Select comum.
